# v2026.7.193 — la vraie cause : VS Code ne sait pas OUVRIR un WebM. Les démos passent en MP4/H.264
1. ✅ **Cause trouvée** (PR *rokucommunity/vscode-brightscript-language#833*, fournie par Frank) : l'**Electron de VS Code n'embarque pas le démuxeur Matroska**. Un `.webm` n'y est donc **jamais** lisible — ni dans une webview, ni dans l'aperçu Markdown, ni dans l'éditeur vidéo intégré, **quel que soit le codec**. Trois versions perdues à chercher ailleurs parce que `canPlayType('video/webm; codecs="vp9"')` répond **« probably »** : Chromium annonce ce qu'il sait *décoder*, sans dire qu'il ne sait pas *démuxer* le conteneur. D'où le lecteur inerte de v190/191 et l'erreur à l'ouverture du fichier.
2. ✅ **Les 3 démos réencodées en MP4/H.264** depuis les MP4 d'origine de Frank : conteneur ISO-BMFF (démuxeur présent) + H.264 (décodeur de la plateforme). **2,03 Mo** à elles trois (`demarrer` 0,28 · `dessiner` 0,54 · `simuler` 1,21), 720p, 4 im/s, `yuv420p`, `+faststart`. CRF 27 retenu après comparaison (CRF 24 : 2,76 Mo · CRF 30 : 1,48 Mo mais le texte des captures se salit).
3. ✅ **Guides FR + EN** : les 3 `<video src="../../media/…mp4">`. Le HTML brut de la v192 est conservé — c'est lui qui rend la démo visible dans l'aperçu Markdown, il ne manquait plus que le bon conteneur.
4. ✅ **WebM banni du paquet et du disque** : les 3 `media/*.webm` supprimés, `media/*.webm` exclu dans `.vscodeignore` (avec la raison écrite noir sur blanc pour ne pas y revenir). Les 3 GIF restent exclus eux aussi : ils ne servent plus qu'au README du marketplace.
