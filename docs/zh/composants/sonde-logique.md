# 逻辑探头

![逻辑探头](../../img/composants/sonde-logique.webp)

一个小小的测量用鳄鱼夹。它不需要接线：只要 **把它放在开发板某个引脚的焊盘上**，它就成为逻辑分析仪的一个 **通道**。每个夹子放下时会获得一种 **颜色**：板上的蓝色夹子就是分析仪中的蓝色通道。

元件栏类别：**测量仪器**。

它只听 **开关量**：0 或 1，以及每次变化的时刻。要观察变化的电压，请用 [示波器](oscillo.md)；要跟踪程序计算出的数值，请用绘图器。

## 引脚

| 端子  | 作用                                                                      |
| ----- | ------------------------------------------------------------------------- |
| **G** | 夹子的 **尖端**，在图形左下角 — 唯一的焊盘                                |

夹子不消耗任何电流，也不施加任何影响：电路的表现与没有它时完全一样。它从不引出任何导线。

## 放置方法

1. 从元件栏拖出夹子。
2. 把它的 **钩子** 移到要监听的引脚的 **焊盘** 上。
3. 松开。夹子夹住引脚，获得一种颜色，该引脚出现在分析仪中。

## 属性

| 属性        | 作用                                                     | 默认值    |
| ----------- | -------------------------------------------------------- | --------- |
| `etiquette` | 通道在分析仪中的名称（`clock`、`data`…）                 | *（空）*  |

标签显示 **在板上夹子旁边**，颜色与通道相同。留空时标签隐藏，通道使用 **引脚名称**（`引脚 8`、`A0`、`GP14`）。

重新打开的电路会把夹子恢复到原来的位置，颜色和名称不变。

## “逻辑分析仪” 标签页

**无需点击任何东西**：只要至少放了一个夹子，**启动仿真** 时就会在 **单独的标签页** 中打开分析仪，可以把它放在 **电路图旁边** — 同时查看波形和接线。板上没有夹子就没有标签页。不小心关掉了标签页：仿真工具栏中会出现一个 **分析仪** 按钮，点击即可重新打开，并保留最近一次的测量。

标签页中 **每个通道一条轨道**，颜色与其夹子相同，顶部有时间标尺。标尺刻度随 **缩放** 变化：查看整个采集时以秒为单位，放大时以毫秒或微秒为单位。在很长的采集中放大很多时，第一个刻度给出完整的时刻（`12.0016 s`），后面的刻度给出相对它的偏移（`+50 µs`、`+100 µs`…）；十字光标则写出时刻的所有有效数字。在边栏中，与信号的两个电平相对，写着它们的 **电压**：高电平为开发板电压（Uno 和 Mega 为 `5 V`，Pico 为 `3.3 V`），低电平为 `0 V`。夹在接口板驱动器后面的夹子会使用该驱动器的电压：**Grove DMX512** 板的 `+` 和 `−` 线为 `3.7 V` 和 `1.1 V`。

多个夹子可以监听 **同一个信号**：在 DMX 板上，夹在 `SIG`、`+` 和 `−` 上的夹子都显示驱动它的引脚发出的数据帧 — `−` 上的夹子是反相的，与真实差分线对一样。

- **滚轮**：以鼠标所在点为中心缩放。
- **拖动**：在记录中移动。
- 工具栏的 **◀ ▶ 箭头**，或 **←** **→** 键：后退或前进半个窗口，缩放不变。
- 工具栏的 **⏮ ⏭ 箭头**：把上一帧或下一帧解码数据的 **起点** 移到左边缘，缩放不变。与前一帧完全相同的帧会被跳过：反复发送同一帧的程序（DmxSimple，约每 2 ms 一次）一次点击就能从一种内容跳到下一种，⏮ 会回到上一组的开头。至少需要一个解码；有多个解码时，按时间顺序在各总线之间跳转，每条总线只与自己的帧比较。
- **悬停**：十字光标给出时刻，以及该时刻每个通道的电平（0 或 1）。
- **标记 M1 和 M2**：停放在标尺下方的一条带上，拖到轨道上时会吸附到最近的边沿；两个都放好后会写出它们之间的时间。带左侧的回收箭头可把它们放回原位。
- **窗口标记 F1 和 F2**：停放在 M1 和 M2 正下方，有自己的回收箭头。放好后，它们之间会拉出一个覆盖所有轨道的 **空心紫色框**：用它框住要检查的内容。这个框 **相对于触发点** 设置：**⏮ ⏭** 从一帧跳到另一帧时，它会放在距新帧起点相同距离的位置，即使你在此期间拖动过曲线；触发点落到别处时它也会跟随。这样就能逐帧查看同一处。它们像 M1 和 M2 一样吸附边沿，但不测量任何东西。
- **整个采集**：把整个采集重新显示在窗口中。
- **实时跟随**：让视图重新贴到采集的末尾，运行时只要没有缩放，它会自动这样做。

每个通道名称下方的 **彩色圆点** 打开其设置：名称、反相、波特率、容差，以及 **隐藏**。隐藏的通道离开屏幕，但保留采集数据；只要有隐藏的通道，工具栏上就会显示一个按钮，可 **重新显示** 全部通道，并显示数量。

边栏中的每个按钮 — 彩色圆点、**T**、**P**、停放的标记、回收箭头 — 悬停时都会在 **提示气泡** 中说明其作用。**T** 和 **P** 的提示还会说明其状态：通道上设置的触发、解码的总线。

仿真之外，标签页显示本次会话的 **最近一次采集**。

仿真运行时，采集数据会 **边采集边写入** 一个单独的文件，即使仿真中断，已测得的数据也会保留。这个文件在 **关闭项目时删除** — 要保留测量结果，请导出（**☰** 菜单，**导出 CSV**）。

项目本身会保存仪器的 **设置**（触发、解码、通道设置、深度）。

## 深度与重新采集

与商用分析仪一样，这台仪器的 **内存有限**：工具栏中的 **深度** 列表设置 **每个通道** 保留的边沿数 — `5 k`、`15 k`、`60 k`（默认）、`250 k` 或 `1 M`。两个最小的选项用于截取一小段，而不必保留好几秒的信号。测量期间，每个选项会在括号中显示 **它能覆盖的时长**（`60 k (≈ 6 s)`），按最活跃的通道估算：DMX 总线或快速时钟比闪烁的 LED 更快填满内存。深度越大时间越长，但标签页的负担也越重。

没有触发时，采集保留 **最新的** 边沿：最旧的边沿逐渐移出，屏幕跟随末尾。有触发时，它在触发边沿 **之前** 保留十分之一的深度，其余部分在 **之后** 填满；满了之后停止，工具栏显示 **保留的信号时长** 和深度：`采集已满：保留了 8.3 s 的数据（每通道 60 k 个边沿）`。重新采集时，只要信号节奏不变，已满的采集会保留相同的时长。

仿真期间更改深度会立即生效：对于已满的采集，会开始新的采集。仿真停止时，所选深度等到下一次运行才生效。

**采样** 列表不会改变这个时长。商用分析仪保存的是采样点：其时长等于深度除以采样率。Kablix 保存的是 **边沿**，时间精确到处理器周期：它的时长取决于信号的节奏，而不是采样。采样只用于 **展示真实仪器会看到什么**：每个边沿被移到其后的采样时刻，同一采样时刻内的两个边沿合并，比一个采样周期更短的脉冲消失，采样过慢的总线会解码错误。而采集本身保留所有精确的边沿：切回 **不限** 即可找回它们，无需重新采集。测量时请保持 **不限**。

工具栏开头的 **↻ 重新采集** 按钮会清除当前测量并从零开始，而不停止仿真；已设置的触发会重新就绪并等待下一个边沿。它只在仿真时可用。

## 导出

工具栏中的 **☰** 按钮打开导出菜单：

- **导出 CSV**：把测量结果保存为 `.csv` 文件，**每个通道一列**（`temps_ms,Sig,DMX-,DMX+`），开头是通道说明。每个边沿在 **同一时刻占两行**：先是之前的电平，再是之后的电平。在电子表格中画成 “带直线的散点图” 时，曲线就是边沿竖直的方波，与屏幕上一样。反相读取的通道（DMX 线对的 `-` 引脚，*反相* 设置）在文件中也是反相的。空单元格表示该通道还没有变化过。正在进行的测量可以在不停止仿真的情况下导出。
- **复制 SVG**：把曲线 **作为图片** 复制到剪贴板，同时提供两种格式：Inkscape 可粘贴的矢量图 (SVG)，以及 Word 可粘贴的普通图片（分辨率为屏幕的两倍）。每个软件会取它能读的那一种。
- **导出 SVG**：同样的图片，保存为 `.svg` 文件。

要只导出一部分，把 **M1** 放在你关心的内容开头，**M2** 放在结尾。这样 CSV 只保留两者之间的边沿，并附上各通道在 M1 和 M2 处的电平。SVG **按当前缩放** 绘制这段范围：屏幕上一个像素就是图片中一个像素，因此导出前放大会让图片变长，缩小会让它变短。没有 M1 和 M2 时，CSV 包含全部测量，SVG 包含屏幕上显示的内容。

图片保留主题颜色和背景、通道名称、解码和标记，但不含标签页上的按钮。在当前缩放下曲线不足 40 像素的范围，或宽度超过 50 000 像素的图片，会被拒绝，并提示应放大还是缩小。

## 触发

通道名称下方的 **T** 菜单：选择 **方向** — *上升* 沿或 *下降* 沿。采集会 **等待** 直到出现第一个这种边沿，然后 **固定在该边沿上**：标尺的 0 时刻就是这个边沿，其他一切都以超前或滞后于它来读取。没有触发时，标尺从仿真启动的时刻开始。

更改设置会 **重新就绪** 等待，**↻ 重新采集** 按钮也一样：已满的采集会开始新的采集。

在解码为 **DMX512** 的通道上，菜单还提供 **`START code 0x00`**：采集固定在照明数据帧 **第一个时隙的起始位** 上，也就是 `BREAK` 和 `MAB` 之后的那一个。值为 `0x00` 的通道不会触发，起始码非零的帧（RDM、文本）也不会。此时按钮显示 `SC`。一位的时长取决于 **通道的波特率**（未填写时为 250 kbaud）：以其他速率发送的帧，只有设置好该速率后才会触发。

在承载另一个解码数据的通道上，菜单提供 **帧起始**：采集固定在就绪后 **第一帧的开头**。帧的开头取决于协议：

- **I²C**：`START`（`START 重复` 只是延续当前帧）；
- **SPI**：`CS ↓`；没有 CS 通道时，为一串时钟的第一个字节；
- **UART**：至少静默一个字符后的第一个字符；
- **1-Wire**：`RESET`；
- **DHT11 / DHT22**：主机的请求。

触发按解码当前的设置读取：更改其通道或速率会重新开始查找。此时按钮显示一条线后跟一个脉冲。

## 解码

通道名称下方的 **P** 菜单：`I²C / TWI`、`SPI`、`UART`、`1-Wire`、`DHT11 / DHT22` 或 `DMX512`。然后要说明 **哪个通道担任哪个角色**：

| 协议              | 需指定的角色                                                                      |
| ----------------- | --------------------------------------------------------------------------------- |
| **I²C / TWI**     | 时钟 (SCL) 和数据 (SDA)                                                           |
| **SPI**           | 时钟 (SCK)、MOSI、MISO、片选 (CS)，以及 **模式** 0 到 3                           |
| **UART**          | 串行线（TX 或 RX），以及 **格式**（`8N1`、`7E1`…）和 **速率**                     |
| **1-Wire**        | 单根线 (DQ)                                                                       |
| **DHT11 / DHT22** | 单根线 (DATA)，以及传感器 **型号**                                                |
| **DMX512**        | 数据线                                                                            |

此时字节和帧标记（`START`、`STOP`、`ACK`、`RESET`、DMX 通道号）会写 **在轨道下方**，各自位于其时间位置。解码只覆盖 **可见部分**：请放大到你关心的那一帧。

所有协议使用相同的颜色：**开始**（起始位、START 条件、CS 选中）为 **绿色**，**结束**（停止位、STOP 条件、CS 释放）为 **红色**，数据为 **蓝色**，帧标记为 **紫色**，校验（`ACK`、校验和）为 **橙色**，1-Wire 命令为 **粉色**，错误为 **品红色**。标准中的术语（`Start`、`STOP`、`BREAK`、`MAB`…）从不翻译：它们就是数据手册中的用语。

### 需要设置的内容

DHT 传感器的 **型号** 无法猜出。DHT11 和 DHT22 发送完全相同的数据帧，时序也相同：**线上没有任何东西能区分它们**。不同的是四个字节的读法 — DHT22 把湿度和温度各用两个字节、以十分之一为单位编码，DHT11 给出整数湿度，温度先是度再是十分之一度（`22.0 °C`：早期型号总是发送 0 的小数位）。选错型号不会报错，只会得到错误的数值。

UART 线的 **速率** 和 **格式** 也一样：两个相近的速率产生相同的边沿却得到不同的字节，同一个信号按 `8N1` 或 `7E1` 读出的字符也不同。字节是乱码时：几乎总是应该先检查速率（它在 **通道** 设置中填写，而不是在解码中 — 同一电路中的两条串行线不一定以相同速率运行）。

而字节的 **进制** 只是一种读法选择，所有协议通用：解码的 **数值** 设置把字节写成 **十六进制**（`0x44`，默认 — 数据手册的写法）或 **十进制**（`68`，程序把读数与数字比较时的写法）。帧标记、命令名称（`CONVERT T`）和测量值（`23.4 °C`）不变。同一采集的两个解码各自保留自己的进制。

**位** 复选框同样适用于所有协议，增加 **二进制显示**：读到的每一位以 `0` 或 `1` 写在承载它的脉冲正下方，按线上的顺序排列，相邻两位之间用一条虚线隔开，正好落在边沿上。在 1-Wire 中，一位的格子从它的低脉冲一直延伸到下一位的低脉冲，包括恢复时间；一串数据的最后一位保留 60 µs 的时隙。这就是接收方读到的数据帧：UART 字符的 `Start` 位和 `STOP` 位，以 **低位在前**（UART、DMX、1-Wire）或 **高位在前**（I²C、SPI、DHT）发送的数据，I²C 字节的 `ACK` 位。字节和标记会下移一行腾出位置。缩小到一位只有几个像素宽时，数字会消失：放大即可看到。切换协议时复选框保持勾选。

### 各解码显示的内容

- **UART** — 每个字符都像在线上一样分段：`Start`（一位，绿色）、数值，可打印时还有字符本身（`0x48 'H'`），然后是 `STOP`（红色）。缺少停止位时在 `STOP` 的位置标出 `帧错误`，校验位错误时在校验位上标出 `校验错误` — 数值仍然显示，由你判断。
- **DMX512** — 每帧按标准的顺序读取：`BREAK`（低电平至少 88 µs）、`MAB`（其后的高电平空闲），然后是十一位的时隙。每个时隙显示其 `Start`（绿色，一位）、十六进制数值和 `STOP`（红色，两位）。第一个时隙是 `START code 0x00`（照明），之后是各通道：`c1=0xC8`、`c2=0x32`… `PAUSE` 表示两个时隙之间的空闲，`MBB` 表示最后一个时隙与下一个 `BREAK` 之间的空闲。起始码非零（RDM、文本…）时照原样显示，不给通道编号。
- **1-Wire** — 只有一根线，没有时钟：承载位信息的是 **低脉冲的时长**。与微控制器一样，解码器在线路下降后 **15 µs** 查看线路：仍为低就是 `0`；已经回高就是 `1`。解码器能识别 `RESET`，并用文字给出常用命令的名称（`SKIP ROM`、`CONVERT T`、`READ SCRATCHPAD`…），因为 `0x44` 什么也说明不了，而 `CONVERT T` 一目了然。命令有自己的颜色 **粉色**：`RESET` 之后的 ROM 命令（`MATCH ROM`、`SKIP ROM`…）以及其后的功能命令（`CONVERT T`、`READ SCRATCHPAD`…）在蓝色的地址和数据字节中很醒目。在命令位置上出现的未知字节 — 来自 DS18B20 以外的其他器件 — 仍为粉色，但没有名称。它总是从事务的 `RESET` 开始读取，即使 `RESET` 已从左侧移出视图：拖动曲线不会改变字节和名称。它不区分是主机还是从机在说话：在线上都是同样的低脉冲，商用仪器只用一个夹子也做不到更好。唯一的例外：`RESET` 刚结束时，传感器会把线路拉低约一百微秒来表示 “我在这里” — 这就是 `应答`（紫色）。没有它，就说明线上没有传感器应答。

  使用 **DS18B20** 时，每次测量分两个事务读取，大约每秒一次：
  1. `RESET`、`应答`、`SKIP ROM`（“我在对所有传感器说话”）、`CONVERT T`（“开始测量”）— 然后在转换期间线路保持空闲（12 位精度时 750 ms）；
  2. `RESET`、`应答`、`MATCH ROM`，后跟目标传感器的 **8 字节地址**（第一个 `0x28` 是 DS18B20 的系列代码，最后一个是校验和），然后是 `READ SCRATCHPAD` 以及传感器返回的 **9 个字节**：前两个是温度（低字节在前，单位为十六分之一度：`0x90` `0x01` = 0x0190 = 400 → 25 °C），最后一个是校验和。

  启动时，程序先查找线上的传感器（`SEARCH ROM`）：对地址的每一位，先读两位再写一位。这些时隙连续出现但不构成字节，下方写出的内容没有意义 — 这是正常的，它只发生一次。
- **DHT11 / DHT22** — 同样只有一根线，但 **它不是 1-Wire**：这里承载位信息的是 **高** 电平的时长（`0` 约 28 µs，`1` 约 70 µs），也没有 ROM 或命令。首先看到的是微控制器的 `请求`，然后是传感器确认收到的 `应答`，接着是测量结果，分 **两行** 显示在曲线下方。第一行把五个字节分开，每个字节一格，格与格之间用竖线隔开：`0x02` `0x37` `0x00` `0xEA` `0x23`。第二行在对应字节下方给出湿度（`56.7 %RH`，在前两个字节下）、温度（`23.4 °C`，在接下来两个字节下）和校验和（`校验和 ✓`，在最后一个字节下）。空间不够时，校验和只显示其对勾。缩小查看时，整帧只有几个像素宽：测量结果会在其右侧一次写出，`56.7 %RH · 23.4 °C · 校验和 ✓`，只要 `请求` 可读，它就可读。**校验和** 会被重新计算并给出结论：`校验和 ✗` 表示连接可疑 — 导线太长、缺少上拉电阻 — 这比五个十六进制字节直观得多。中途被截断的帧会如实标出（`17/40 bits`），而不是随意补全。
